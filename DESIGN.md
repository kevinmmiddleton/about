# DESIGN.md: middleton.io

The visual system for Kevin Middleton's site. Written for agents: read this before
changing any styling, so new work inherits the system instead of the model's defaults.

**Source of truth for values: the stylesheets themselves.** The tables in Colors are
generated by `tools/design-extract.mjs`, which reads *computed* values out of headless
Chrome per surface and per colour scheme. Do not hand-edit them, and do not add a
hand-counted number anywhere in this file. See *Checking this document*.

> **Every rule here carries a scope tag.** `[all]` `[homepage]` `[blog]` `[kevinos]`
> `[cases]`. A rule with no tag is a bug in this document. This is not decoration:
> the previous version stated "every `<img>` carries width/height" and "one `<h1>`
> per page" as if site-wide, and KevinOS drifted to 52 dimensionless images and two
> `<h1>`s without ever violating anything written down.

## Overview

Warm, editorial, human. Not a SaaS template, not a dark-mode dev portfolio.
The site reads as a person who builds things.

**Surface modes** (what each page is *for*):

| Surface | Mode | Stylesheets it actually loads |
|---|---|---|
| `/` homepage | **persuade**: recruiters deciding in ~30 seconds | `fv.css` only |
| `/blog/` | **read**: long-form, comfortable measures, minimal chrome | `fv.css` then `blog/blog.css` |
| `/casestudies/` | **persuade**: depth for someone already interested | `fv.css` (`body.p-cases`, `body.p-case`) |
| `/kevinos/` | **experience**: a deliberate retro-OS bit | `kevinos/kevinos.css` only |
| `/prototypes/`, micro-sites | **experience/persuade**, each with its own liberty | varies |

**When modes conflict, the mode wins over consistency.** `[homepage]` `[cases]`
On a persuade surface, proof-visibility beats visual tidiness: if a change makes the
page more consistent but buries a number, a logo, or a link to evidence, do not make it.

## Colors

There is no single brand hex. The system is built on **roles**, not names, and most
roles flip between light and dark. Six named hues carry identity; everything
structural is neutral.

`--invert` is separate from `--ink` on purpose: `--ink` also carries text and borders,
which invert with the mode, and the contrast panel must stay a panel.

Each hue has a `c1`–`c6` triad so you never have to decide how to use it:

- `--cN-line`: outline. Moves per mode, because it must clear 3:1 against the page.
- `--cN-fill`: the pure hue. Never moves; a filled chip brings its own ground.
- `--cN-on`: text on that fill.
- `--cN-text`: the hue used *as text on the page*. Moves per mode.

`c1` gold, `c2` madder, `c3` viridian, `c4` cobalt, `c5` plum, `c6` fuchsia. Cobalt,
plum and fuchsia lift their `line` and `text` values in dark mode because the base
hues fall under the floor on a dark page. `--swap-1..4` exist for the same reason in
chip contexts.

### Rules

1. `[all]` **Never hardcode a hex in new work.** Use a token. The exception is a value
   sitting on a fixed ground of its own, such as the lightbox scrim, where the page
   tokens are the wrong reference. Comment it when you do.
2. `[all]` **Ask which ground it lands on before picking a token.** See *The two-ground problem*.
3. `[all]` Elements with a fixed background of their own render the same in both modes.
   Do not write dark-mode overrides for them.
4. `[homepage]` Tokens scoped to `.fv` (`--gold-rule`, `--tag-line`) do not exist
   anywhere else. At `:root` they compute to empty. Do not use them on the blog.

## The two-ground problem

The most repeated trap here. A colour drawn **on the page** and the same colour drawn
**on the `--invert` panel** are never the same value at the same time, because the two
grounds move in opposite directions between modes.

```
                 light page   dark page
--gold-rule        #815B0C     #E8A317     <- gold ON THE PAGE
--gold-on-invert   #E8A317     #815B0C     <- gold ON THE PANEL
```

Exact inverses. This is why each needs its own token, and why reusing one for the
other is always wrong in one mode.

It has bitten twice. Raw `--marigold` measures **1.97** against the light page, so an
open Experience row drew its bottom rule in a colour that made the edge *disappear*
rather than highlight, and it looked correct to anyone testing in dark mode only.
Before reaching for an accent, ask what is behind it, and check the other theme.

## Typography

`[homepage]` `[blog]` `[cases]` Two families, both system stacks. **No webfont is
loaded.** `[kevinos]` KevinOS is the exception and does load Google Fonts (Outfit and
JetBrains Mono).

- `--sans` → `"Helvetica Neue", Helvetica, Arial, sans-serif`
- `--mono` → `"SF Mono", Menlo, ui-monospace, "Cascadia Mono", Consolas, monospace`

Mono marks the *ledger* register: dates, sector pills, skill tags, kickers, mode
switches, counters.

### The scale

`[homepage]` The page currently renders far more sizes than this because it grew
without a documented ramp. **New work picks from these steps rather than inventing a
size.** Headings are fluid, never fixed; tracking tightens as size grows.

| Step | Value | Weight | Used for |
|---|---|---|---|
| hero | `clamp(2.1rem, 7.4vw, 5.4rem)` | 800 | the one page-defining statement |
| display | `clamp(1.9rem, 6vw, 4.2rem)` | 800 | section headline |
| section | `clamp(1.6rem, 3.4vw, 2.5rem)` | 800 | subhead |
| card | `1.2rem` | 800 | card title |
| body | `.9rem` / 1.6 | 400 | prose |
| ledger | `.62rem` mono, `.1em`, uppercase | 700 | metadata, controls |
| micro | `.53rem` mono, `.1em`, uppercase | 700 | the smallest label |

Tracking: `-.02em` to `-.04em` at display sizes, `line-height` near `.95`–`1.05`.
`micro` is the floor; below it, legibility fails before contrast does.

## Layout

- `[homepage]` A bento grid; cards are self-contained and each states one idea.
- `[all]` **Cap and centre long-form content.** Computed caps are in the generated
  block above. Read them there rather than trusting a number in prose.
- `[all]` **Measure prose in `ch`.** Established: `68ch` descriptions, `72ch` list
  items, `62ch` standfirsts. 45–75ch is the readable band. A correct measure can still
  *look* broken if the space beside it is empty; fix the emptiness, not the measure.
- `[all]` **When content wraps to its own row, centre it.** Prefer container-relative
  solutions (flex-wrap with a sensible `flex-basis`, caps) over `@media`. This matters
  inside KevinOS windows, which are narrow *within* a wide viewport, so viewport media
  queries never fire.
- `[all]` Wide content (tables, code, diagrams) scrolls inside its own container; the
  page body never scrolls horizontally.

### Spacing

`--spacing-xs .25rem`, `sm .5rem`, `md .85rem`, `lg 1.15rem`, `xl 1.8rem`, `2xl 2.8rem`.

`[blog]` **The blog overrides these on unscoped `:root`.** `--spacing-md` computes
`1.5rem` there, not `.85rem`. Check the generated block before assuming a value holds
on a surface.

## Elevation & Depth

`[homepage]` **The homepage is flat by intent.** Depth comes from 1–2px rules and
`--bg2`, not shadow. This is a Swiss-editorial system, not a card-and-shadow one.
Do not read the absence of shadows as a deficiency to correct.

`[kevinos]` KevinOS is the opposite and correct on its own terms: shadow, glass and
`backdrop-filter` carry depth there.

Shadow tokens exist for overlays and for KevinOS. They deepen substantially in dark
mode, because a shadow on a dark page needs far more alpha to read at all. Values are
in the generated block.

## Shapes

`[homepage]` `--r: 10px` is the house radius; `--radius-lg` aliases it;
`--radius-full: 99px` for pills.

`[blog]` `[cases]` Other scopes redefine these. The blog sets `--radius-lg: 1.5rem`
and `--radius-md: 1rem` on `:root`; `body.p-recipes` carries a full 8/12/20px ramp.

## Components

`[homepage]` Match these rather than inventing a new one.

**Cards.** `.bc` sets `border-radius: var(--r)`, `padding: 1.05rem`, `display: grid`
with `align-content: space-between`, and `position: relative`. Hover lift is
`translateY(-6px)`. `.bento` arranges them `repeat(3,1fr)` with rows `7.6rem 15.8rem`.

**The "go somewhere" affordance** is `.go`: a full-width bar pinned to the bottom of
the card over `--scrim-dark`, or `--scrim-light` on the marigold card. It is a
labelled bar ("Book a slot", "Boot it up"), not a bare glyph in a corner.

**Outbound links in prose** end with `.arw-ne`, a drawn `↗` at `.72em` using
`currentColor`, plus a visually hidden "(opens in a new tab)". `.arw` is the same idea
for the `0 → 1` form.

**The CTA pill** is `.cta`: `--marigold` ground with `--on-mari` text,
`translateY(-2px)` on hover.

`[all]` **No layout shift on hover.** Use shadow and transform, never padding, border
width, or font size.

`[all]` **New interactive elements carry `plausible-event-name=`.** `PRODUCT.md` owns
the goal list. A card without one ships untracked.

## Interaction & accessibility

`[all]` **Focus** is `outline: 3px solid var(--ink); outline-offset: 2px`. On a fixed
dark ground such as the lightbox, gold substitutes, since `--ink` would vanish.
`[kevinos]` KevinOS has no global `:focus-visible` rule; it should.

`[all]` **Target size: WCAG 2.5.8 AA.** 24×24 minimum, or the spacing exception (a
24px circle centred on each undersized target must not intersect a neighbour's).
44×44 is 2.5.5 **AAA**, not the bar. New primary actions should still aim for 44.

`[all]` **State never relies on colour alone.** An open Experience row changes its
rule colour *and* rotates its `+` glyph.

`[all]` **Reserve space for images.** Every `<img>` carries `width`/`height` alongside
`width:100%; height:auto`. `[kevinos]` KevinOS does not currently comply.

`[all]` **A modal overlay takes `aria-modal`, a focus trap, Escape, and focus returned
to whatever opened it.** `[kevinos]` KevinOS windows are the deliberate exception:
they are a non-modal multi-window desktop, `role="dialog"` **without** `aria-modal`.

`[all]` **Reduced motion:** add a `prefers-reduced-motion` block scoped to the surface
you are working on. Do not assume an existing one covers you; the `.fv`-scoped block
never reaches the blog.

## Cascade and scoping

**This replaces the old "the palette is declared in six places" advice, which sent
agents to edit blocks that cannot reach the homepage.**

Order, weakest to strongest:

```
:root                          base layer, reaches every surface
  @media (prefers-color-scheme) mode override
    :root[data-theme=...]       manual override  <- BLOG AND SLIDES ONLY
      .fv                       homepage         <- WINS over all of the above
      body.p-case / p-cases     case studies
      body.p-slides             slides
      body.p-recipes            recipes
```

`.fv` is a `<div>` at `index.htm:109`, not `<html>`, and it declares its own tokens.
A descendant's own declaration always beats an inherited one, so **`:root[data-theme]`
is inert for the entire homepage.**

- `[homepage]` To change a homepage colour, edit `.fv` and `.fv` under dark. Nothing else.
- `[blog]` `:root[data-theme]` affects the blog and slides.
- `[all]` For a token only one component needs, declare it scoped and stop there.
  That is how `--gold-rule` and `--tag-line` were added.

**Which scope do I write in?** Bare `.thing` reaches every surface including the blog.
`.fv .thing` is homepage-only and is the default for homepage work.
`body.p-* .thing` is that page type only.

**Undocumented name collisions:** `--r` / `--radius` / `--radius-lg`;
`--shadow-1` / `--shadow-06`; `--rule` / `--border`. Pick deliberately.

**Compatibility shims.** `--surface`, `--border`, `--text-muted` and similar exist as
bridges for older page-scoped CSS. They are **not** the design system. Write new work
against `--bg2`, `--rule`, `--ink2` directly.

## Known traps

Each of these has shipped a bug here.

**Descendant selectors leak into children.** `.rrow-tags span` matched the spans
*inside* a tag as well as the tag itself, so a drawn arrow inherited the pill's
padding and border and could never reach its specified size. Use `>` when you mean
"the element", not "anything inside it".

**`grid-row: 1 / -1` does not span what it looks like.** With no declared
`grid-template-rows` every row is implicit, so `-1` resolves to the end of the
*explicit* grid, line 1, and the span silently collapses to a single row. If a column
must sit beside multi-element content, wrap that content so each column is one item.

**`:has()` contributes its argument's specificity,** and equal specificity resolves by
source order. A `:has()` rule can beat a plainer one you expected to win.

**Custom properties inherit downward only.** Setting `--x` on a child is invisible to
its parent. If a container styles itself from a token, set the token on the container.

**A string in a comment is not a declaration.** The previous version of this document
stated the blog cap as 1040px; that string existed only inside a comment reading
"Was 1040px". Strip comments before counting or matching anything.

**Cache stamps go stale silently.** Assets are referenced as `file.css?v=<md5head8>`.
If the file changes and the stamp does not, the mechanism does nothing while still
looking like it works. Run `node tools/stamp-assets.mjs` before a deploy.

**Verify what the user sees, not what you changed.** The recurring failure here has
been fixing the data and not checking the render, or fixing a container and not its
contents.

## Other surfaces

**KevinOS**. `kevinos/kevinos.css` and `kevinos/index.html`. Its own world: Outfit
and JetBrains Mono via Google Fonts, Georgia for serif accents, dark as the `:root`
default. It has a fixed icon-tile palette that deliberately does **not** invert. It
does not load `fv.css`, and it references a few tokens that exist nowhere on that
surface.

**Blog**. Loads `fv.css` **then** `blog/blog.css`. It inherits the `:root` token
layer **only**: blog pages carry no `.fv` wrapper, so every `.fv`-scoped rule, which
is a substantial share of `fv.css`, never reaches them. It also runs a **competing
neutral palette** rather than a shim layer, and defines `--text-primary`, `--card-bg`
and `--coral-text` as live tokens. Those exist and are load-bearing; do not delete
them because they are absent from `fv.css`.

## Do's and Don'ts

### Do not produce `[homepage]` `[blog]` `[cases]`

- Purple/violet gradients, glassmorphism, neon-on-black "AI" aesthetics.
- AI beige, generic drop shadows on everything, decorative motion with no meaning.
- Stock SaaS buzzwords: *streamline, empower, supercharge, world-class,
  enterprise-grade, next-generation, cutting-edge, seamless*. Say the concrete thing.
- Em dashes in polished copy. Use a period or restructure. (House rule.)
- "Shape" as a noun for tone/structure/feel. (House rule.)
- Gendered pronouns for the AI assistant. Use "my assistant" or "it". (House rule.)

> `[kevinos]` **KevinOS is exempt from the visual bans above.** Its gradients, glass
> and saturated hues are the deliberate aesthetic, not drift. A compliance pass that
> strips them is a regression, not a fix.

### Always

- `[kevinos]` **Never redesign KevinOS toward contemporary taste.** Fix bugs, spacing
  and a11y; leave the aesthetic alone.
- `[all]` Surfaces share tokens but are *not* meant to look identical. Respect the mode.
- `[all]` Images: JPEG for anything that doubles as `og:image`. WebP only for inline
  images needing alpha. Never ship multi-MB originals; serve a thumbnail at display
  size and keep the original for the lightbox.
- `[all]` Every image has `alt`. One `<h1>` per page.
- `[all]` Never claim a fix works without measuring it in **both** themes and at a
  phone width, having asserted the viewport actually applied.

## What this document does not govern

Stated explicitly so nobody assumes coverage that is not here:

- **Content and copy decisions.** `PRODUCT.md` owns those, including the analytics goals.
- **`is-off`.** `.fv .is-off{display:none}` hides `#looking` ("What I'm Looking For"),
  Skills & Expertise, and Certifications on the homepage. **This is deliberate.**
  Do not "restore" them.
- **Micro-sites and `/slides/`.** Each keeps its own liberty by design.
- **The case-study and recipes page-scoped blocks**, beyond the scoping rules above.
- **Taste.** Judgements like "this feels balanced" are not encoded here. Earlier
  versions carried unverifiable prose of that kind; it was removed, because a claim no
  one can check is a claim no one can maintain, and it is what let the previous
  version rot into something actively misleading.
